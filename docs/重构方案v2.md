# 幕燃 (Muran) MVP v3 重构方案

## 目标

将当前三层分离架构（Router → Storage → db_store）重构为 Feature Module 架构，按用户功能组织代码，建立显式跨模块依赖规则。

## 核心原则

- **按功能组织**：每个 feature 对应一个用户可执行的操作（管理项目、生成分镜、生成视频...），不按数据实体拆分
- **厚 Service**：Service 是唯一的业务入口，Router 只做 HTTP 协议转换
- **显式依赖规则**：跨模块调用走 service 边界，事务性 helper（`change_points`、`add_ai_job`）可在 db 层跨 feature 调用
- **保持函数式风格**：不加 class/接口抽象，纯函数 + 模块组织

## 单 Feature 内部结构

```
feature/
├── router.py      # HTTP 端点，仅做协议转换，不处理业务异常
├── service.py     # 业务流程、事务边界，raise 具名业务异常
└── db.py          # SQLAlchemy 查询/写入函数（纯数据访问）
```

## 跨模块依赖规则

```
router  →  service                       # Router 只能调 Service
service →  本 feature 的 db              # Service 可以调自己的 db
service →  其他 feature 的 service         # 跨模块走 service 边界
db      →  事务性 helper 可跨 feature      # change_points、add_ai_job 例外
db      ✗  其他 feature 的 service         # db 层不调 service
```

## 错误处理模式

```python
# features/errors.py — 具名业务异常
class DomainError(Exception):
    """业务异常基类，由 service 层抛出，由 main.py 的全局异常处理器转换为 HTTP 响应。"""
    def __init__(self, detail: str):
        self.detail = detail

class NotFoundError(DomainError): ...
class BadRequestError(DomainError): ...
class InsufficientPointsError(DomainError): ...
class ForbiddenError(DomainError): ...
class UnauthorizedError(DomainError): ...
class ConflictError(DomainError): ...
class ServiceUnavailableError(DomainError): ...

# features/router_utils.py — 状态码映射
ERROR_STATUS = {
    BadRequestError: 400,
    UnauthorizedError: 401,
    InsufficientPointsError: 402,
    ForbiddenError: 403,
    NotFoundError: 404,
    ConflictError: 409,
    ServiceUnavailableError: 503,
}

# main.py — 全局异常处理器（替代旧的 @api_endpoint 装饰器）
@app.exception_handler(DomainError)
async def domain_error_handler(request, exc):
    return JSONResponse(
        status_code=resolve_status(exc),
        content={"detail": exc.detail},
    )

# feature/router.py — 直接调 service，无需装饰器
@router.post("/episodes/{episode_id}/storyboard")
def generate_storyboard(episode_id: str, ...):
    return service.generate_storyboard(user, episode_id, payload)

# feature/service.py — 只管 raise 具名异常
def get_project(user, project_id):
    result = db.get_project(user, project_id)
    if result is None:
        raise NotFoundError("项目不存在")
    return result
```

### 为什么用全局异常处理器而非装饰器

旧方案 `@api_endpoint` 装饰器将同步函数包装为 `async def`，导致 FastAPI 在 event loop 中直接执行同步 DB 操作，可能阻塞请求处理。全局异常处理器让 FastAPI 自动将同步端点放在线程池中执行，同时统一处理 `DomainError` → HTTP 响应的转换。

## 本地开发环境

- **Docker PostgreSQL 16**：`docker compose up -d` 启动本地数据库
- **环境变量隔离**：`backend/.env.local` 覆盖 `backend/.env` 中的 `DATABASE_URL`
- **Alembic 迁移**：`cd backend && alembic upgrade head`

```bash
# 启动步骤
docker compose up -d
cp backend/.env.local.example backend/.env.local
cd backend && alembic upgrade head
python -m uvicorn app.main:app --reload
```
